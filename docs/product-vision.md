# 产品愿景

> 状态：**FINAL BUSINESS BASELINE / Accepted**
>
> 业务总入口：`business-baseline.md`。

## 1. 产品定位

本产品是一套面向个人持续学习的 **AI Study Workspace**。它把用户已经拥有但分散、非结构化的教材、PDF、图片、ZIP、文本和管理员录入资料，转化为可追溯的结构化学习内容，并围绕知识点建立学习、练习、复习、考试、能力诊断和学习计划闭环。

产品不是简单的“AI 聊天壳”，也不是只做题库或只做笔记的软件。

核心价值来自三层：

```text
资料层：把真实资料保存、解析、结构化、可追溯
   ↓
知识层：形成知识点、题目、笔记和来源关系
   ↓
学习引擎：学习、练习、错题、复习、考试、掌握度、计划
```

AI 横跨三层提供增强，但不替代原始资料和业务事实。

## 2. 目标用户

第一阶段核心用户是有明确学习目标、拥有自己的教材/资料、希望长期管理学习过程的个人用户。

典型场景：

- 资格/认证考试准备
- Java 等技术栈系统学习
- 数据库、计算机网络、操作系统等专题学习
- 长期资料积累与反复复习

系统同时包含 ADMIN 角色，用于内容录入、审核、题库/考试维护和系统管理。

## 3. 核心痛点

### 资料碎片化

资料分散在 PDF、照片、ZIP、Markdown、笔记等不同载体中，难以统一组织和检索。

### AI 与原资料脱节

普通 AI 问答容易“讲得像对的”，但用户无法快速确认它到底来自教材哪一页。

### 学习行为断裂

看书、记笔记、刷题、错题、复习和考试往往分散在不同工具中，无法形成统一能力状态。

### 多主题互相污染

数据库、Java 等不同学习主题如果共用一套知识检索/题库上下文，AI、题目和统计容易串数据。

### 考完只有分数，没有下一步

普通考试系统通常只给分数，本产品需要把考试结果继续转成知识点诊断、掌握度变化和下一轮学习计划。

## 4. 核心价值主张

### 资料可追溯

任何从真实资料派生的知识点、题目、AI 解释都尽可能能回到 Source / Page / ContentBlock。

### LearningSpace 真隔离

用户进入“数据库管理”后，默认不会看到/检索/组卷到“Java 学习”的内容。

### 练习与考试分工明确

- Practice：训练。
- Exam：测量。

两者共同更新学习状态，但交互和规则不同。

### 学习状态可累积

系统持续积累 WrongQuestion、Review、Exam、Mastery 等证据，而不是每次打开都重新开始。

### 学完之后知道下一步

StudyPlan 根据当前空间内的学习状态安排下一步学习、练习、复习和考试。

## 5. 产品原则

1. 原始资料优先于 AI 派生结果。
2. 派生内容必须可识别来源类型。
3. LearningSpace 是一级业务隔离边界。
4. 服务端是业务事实唯一权威入口。
5. Practice 与 Exam 是两个独立核心流程。
6. AI 基于资料回答时应提供来源。
7. 自动化结果必须允许人工审核和修正。
8. 第一版优先完成真实闭环，不堆高级基础设施。
9. 本地开发与未来服务器部署使用同一业务架构。

## 7. Desktop / Admin / Android 分工

Desktop 是主要学习客户端和本地资料入口。

Admin Web 是内容生产、审核、治理和系统管理后台。

Android 后续复用同一 Backend，重点承载移动学习、练习、考试、复习和拍照导入。

## 8. 第一版验收目标

使用真实的《数据库系统工程师教程》样本完成从 ZIP 图片到学习闭环的一次完整验证，并同时建立“Java 学习”空间验证 LearningSpace 数据隔离。
